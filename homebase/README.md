# homebase/ — the app

The React app that powers Homebase. For the user-facing description and "try it" link, see the [root README](../README.md). For contribution conventions, see [CONTRIBUTING.md](../CONTRIBUTING.md). This file is the engineering orientation: what's in here, how to run it, how it's wired.

## Stack

- **[React 19 + TypeScript](https://react.dev/)** — frontend
- **[Vite+](https://viteplus.dev/)** — unified toolchain (`vp` CLI), bundling Vite + Vitest + Oxlint + Oxfmt + tsdown under one binary
- **[Tailwind CSS v4](https://tailwindcss.com/)** — styling via `@tailwindcss/vite`. Two color registers — a warm cream "strategy" scope on `/`, `/about`, `/horizon/:id`, and a clean-white register on `/morning` and `/settings`. Tokens defined in `src/index.css` under `@theme` and the `.strategy-scope` block.
- **[TanStack Router](https://tanstack.com/router)** — file-based routing. Route tree auto-generated into `src/routeTree.gen.ts` during build.
- **[Zustand 5](https://zustand-demo.pmnd.rs/)** — store layer. Two stores: `store/strategy.ts` for the accordion, `store/ritual.ts` for the daily page + the user's HomebaseConfig.
- **[CodeMirror 6](https://codemirror.net/)** — markdown editor under each writing field (`components/RitualEditor.tsx`, `components/MarkdownEditor.tsx`).
- **[vite-plugin-pwa](https://vite-pwa-org.netlify.app/)** — manifest, service worker, install prompt.
- **[@dnd-kit](https://dndkit.com/)** — drag-and-drop on `/settings`.
- **Vitest + Testing Library + jsdom** — unit and component tests.

## Architecture in one paragraph

The app is a PWA, hosted as a static site on GitHub Pages. There is no backend. State persists to a folder the user picks via the [File System Access API](https://developer.mozilla.org/en-US/docs/Web/API/File_System_Access_API); the picked directory handle survives reloads in IndexedDB. The app reads `homebase.config.json` (slot list + briefing) and per-day `YYYY-MM-DD.md` files from that folder. Writing happens debounced as you type. Both stores own a `loadToday`-style bootstrap that gates render on disk-loaded state, so editors never mount with stale-empty content.

## Commands

Run from the repo root or from `homebase/` — the root-level `pnpm` scripts forward here.

```bash
pnpm dev          # Vite dev server at http://localhost:47823
pnpm test         # vitest run once
pnpm test:watch   # vitest watch mode
pnpm typecheck    # tsc --noEmit
pnpm check        # format + lint (vp check)
pnpm check:fix    # auto-fix formatting and lint
pnpm build        # production build (vp build && tsc --noEmit)
pnpm preview      # serve the built dist/ locally
```

The dev server is pinned to **port 47823** (`strictPort: true` in `vite.config.ts`) to dodge collisions with other Vite projects on the same machine.

**Build order matters:** `pnpm build` runs `vp build && tsc --noEmit`, not the other way around. The TanStack Router plugin generates `src/routeTree.gen.ts` during the build pass, and `tsc` can't find it if it runs first. After a fresh clone, run `pnpm build` (or `pnpm dev`) once to generate the tree before `pnpm typecheck` will be happy.

## Where data lives

- **`homebase.config.json`** — slots + briefing config, written next to the user's day files. See `lib/config.ts` for schema and validation.
- **`YYYY-MM-DD.md`** — one file per day, with `## slot-id` sections inside.
- **`<slot-id>/state.md`** — persistent body for workspace slots.
- **Strategic horizons** live in a separate folder (a different directory handle, persisted in IndexedDB). `life-values.md`, `life-goals.md`, `year-2026.md`, `month-2026-05.md`, `week-2026-W19.md`.
